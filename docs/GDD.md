# 내 아이의 MBTI · 전체 기획서

- 최종 수정일: 2026-11-17
- 버전: 웹 시제품(별도 버전 번호 없음, `main` 브랜치 = 배포본)
- 구현 파일: `index.html` 한 파일(HTML, CSS, JS). 그림은 `assets/`, 손그림 UI 조각은 `assets/ui/`

## 1. 개요

만 2~7세 아이의 타고난 기질을 MBTI처럼 네 글자로 읽는 부모용 영유아 기질검사 웹앱이다.
부모(또는 양육자)가 최근 한 달간 아이의 모습을 떠올리며 답한다. 엄마, 아빠, 할머니처럼 양육자마다 따로 검사하고 결과를 비교할 수 있다([양육자별 검사 세부 기획서](systems/caregivers.md)).
결과는 양육 참고용이며 의학적 진단이나 발달 평가를 대신하지 않는다. 화면 문구도 진단처럼 쓰지 않는다.

정밀 리포트는 두 갈래로 나뉜다.

- **기질 결과**: 타고난 성향. 4축, 세부 기질 12가지, 네 글자 유형과 별명
- **성격 결과(자라는 힘)**: 경험으로 자라는 힘. 끈기, 스스로 힘, 함께 힘

화면 기준은 휴대폰 세로 화면 한 줄 배치(본문 최대 폭 480px)이다. 아트는 색연필·크레용 손그림 콘셉트(C4)다.

## 2. 검사 구성

| 항목 | 정밀검사(유일한 검사) |
|---|---|
| 문항 | 66문항 = 기질 48 + 자라는 힘 18 |
| 시간 | 약 10분 |
| 결과 | 정밀 리포트(기질 탭 + 성격 탭 + 양육자 비교 + 달라진 점). [결과 화면 세부 기획서](content/report.md) |

- 무료 12문항 간이검사는 없앴다(2026-11-16 원더 결정). 결제 전에는 '샘플 리포트 보기'로 결과 모양을 보여 준다. 문항 데이터의 `free` 표시와 `FREE` 목록은 쓰지 않지만 남아 있다.
- 응답: 5점 척도(전혀 아니다 ~ 매우 그렇다) + '잘 모르겠다'. 문항마다 장면 예시를 함께 보여 준다.
- 기질 4축(문항 데이터 `index.html` 의 `AX`): 탐험·관찰(E/I), 섬세·무던(S/N), 표현·잔잔(F/T), 리듬·자유(J/P). 축마다 세부 기질 3개, 세부 기질마다 4문항.
- 자라는 힘(문항 데이터 `GR`): 끈기, 스스로 힘, 함께 힘. 척도마다 6문항.
- 16유형 별명은 `NICK`, 유형 풀이 문구는 `P`, 문항 예시는 `EXS` 에 있다.

### 채점 규칙

- 응답 1~5점. 역채점 문항은 6에서 뺀다.
- '잘 모르겠다'는 점수에 넣지 않는다. 같은 세부 기질의 나머지 문항으로 계산한다. 한 세부 기질 문항을 모두 모르겠다고 하면 '정보 부족'으로 표시한다.
- 세부 기질 점수 = 문항 평균을 0~100으로 환산. 축 점수 = 세부 기질 3개의 평균.
- 50 이상이면 앞 글자(E, S, F, J), 미만이면 뒤 글자(I, N, T, P).
- 50에서 20 이상 떨어지면 '뚜렷함', 8 이상이면 '약간', 그 안이면 '균형에 가까움'.
- 자라는 힘: 65 이상 '탄탄함', 40~64 '고르게 자라는 중', 40 미만 '지금 자라는 중'.
- 응답 일관성: 같은 세부 기질 안에서 정방향 문항 평균과 역방향 문항(뒤집은 값) 평균의 차이. 0.9 미만 높음, 1.5 미만 보통, 그 이상 낮음. 20문항 넘게 모두 같은 값이면 낮음.
- 또래 비교(백분위)는 아직 없다. 점수는 아이 안의 경향이다.

## 3. 화면 흐름

화면 주소는 `#` 뒤 이름으로 정한다. 아래 메뉴는 3칸이다: 홈, 리포트, 공유.

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `#home` | 자녀 고르기(아이 칩, '+ 아이 추가'), 아이 이름·연령·답하는 사람, 양육자별 검사 현황, 정밀검사 카드(지금 가격), 샘플 리포트, 공유 안내, 기록 파일 저장·불러오기 |
| 결제 | (주소 없음) | 검사 1회 결제 화면(첫 검사 / 양육자 추가 검사 / 다시 검사하기). 아래 메뉴 숨김 |
| 검사 | (주소 없음) | 한 문항씩 답하기. 아래 메뉴 대신 '이전 문항', '나중에 하기' |
| 리포트 | `#report` | 맨 위 아이·양육자 고르기 + 정밀 리포트 4탭. 아래에 공유 안내, '다시 검사하기 · $0.50' |
| 공유 | `#share` | 결과 카드 공유, 공동 양육자 초대, 앱 추천, 초대받은 사람의 '결과 보내기' |
| 공유 링크 도착 | `#land` | 공유 링크로 들어온 사람에게 보이는 화면(친구 결과, 앱 추천, 초대장, 도착한 결과) |
| 문항과 정책 | `#blueprint` | 내부 검토용. 검사 구성, 가격 정책, 채점 규칙, 전체 문항 |

- '검사 시작'을 누르면 지금 양육자의 검사를 아직 결제하지 않았으면 결제 화면, 결제했으면 검사(이어 하기)로 간다.
- 리포트는 정밀검사 66문항을 모두 답해야 열린다.
- 리포트 안의 탭 전환은 주소와 아래 메뉴 켜짐 표시를 바꾸지 않는다.

## 4. 결제와 공유

검사 1회마다 결제한다. 이용권, AI 대화, 사용량 한도는 없앴다(2026-11-16 최종 스펙).

| 항목 | 값 |
|---|---|
| 아이마다 첫 정밀검사 | $1 |
| 그 밖의 검사 | $0.50: 같은 아이의 다른 양육자 검사, 다시 검사하기(횟수 제한 없음) |
| 형제·동생 | 새 아이로 등록하면 그 아이의 첫 검사 $1 |
| 결과 보기 | 기간 제한 없음 |

- 가격은 `index.html` 의 `PRICE` 한곳에서 바꾼다. 가격이 바뀔 수 있다(원더).
- 시제품이라 실제 결제는 연결되어 있지 않다. 결제 버튼을 누르면 바로 검사가 열린다. 실제 앱은 구글 플레이 인앱 상품(소모성) 2개로 연결한다.
- 공유(카카오톡, 공동 양육자 초대와 결과 합치기, 앱 추천)와 기록 파일은 [결제·공유 세부 기획서](systems/pay-share.md).

## 5. 저장

브라우저 `localStorage` 의 `aigyeol` 키에 JSON 하나로 저장한다. 서버 저장은 없다. 지금 고른 아이의 기록은 `st` 바로 아래에, 다른 아이들은 `st.kids[id]` 에 있다.

| 필드 | 뜻 |
|---|---|
| `kid`, `korder`, `kids` | 지금 고른 아이 id, 아이 순서, 다른 아이들의 기록 `{id: {아래 아이 필드}}` |
| `key` | 아이를 기기 사이에서 알아보는 무작위 값(초대·결과 링크에 실림) |
| `name`, `age`, `who` | 아이 이름, 연령, 지금 고른 양육자 |
| `ans`, `date`, `qd`, `prev`, `paid` | 지금 양육자의 답, 마지막 응답일, (예전) 간이검사 표시, 이전 기록, 이번 검사 결제 여부 |
| `cgs` | 다른 양육자들의 기록 `{이름: {ans, date, qd, prev, paid, recv}}`. `recv` 는 다른 휴대폰에서 받은 결과 |
| `buys` | 이 아이의 결제 기록 `[{t, kind, who, price}]`. 하나라도 있으면 다음 검사는 $0.50 |
| `ext`, `inv` | 초대로 받은 아이(첫 검사를 다른 휴대폰에서 결제함), 받은 초대 `{from, at}` |

- 예전 기록(`pass`, `use`)은 처음 열 때 옮긴다: 이용권을 산 적이 있으면 결제한 검사로 보고 `pass`·`use` 는 지운다.
- 리포트에서 어느 탭을 보고 있었는지는 저장하지 않는다.

저장 항목, 다시 검사하기, 전부 지우기 동작은 [저장 세부 기획서](systems/save.md)에 있다.
