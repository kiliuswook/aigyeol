# 앱 속도(체감) 원칙

2026-11-20 원더 "간단한 앱인데 기기에서 좀 느리게 느껴지네" 로 손본 것과 지킬 것.

## 앱 켜기
- `main()` 에서 화면 전에 기다리는 것은 문항(content.json)·9조각 테두리 그림·이 폰 기록뿐. 셋은 동시에 읽는다.
- Firebase(로그인·동기화)는 `runApp` 뒤에 연다. 앞에서 기다리면 그만큼 빈 화면이 길어진다.
- 광고(동의 창 + AdMob 초기화)는 스플래시 영상이 끝나고 타이틀로 넘어갈 때(`intro.dart` toTitle) 시작한다. 영상과 겹치면 영상이 끊긴다.
- AndroidManifest 의 `OPTIMIZE_INITIALIZATION`·`OPTIMIZE_AD_LOADING` 으로 광고 SDK 일을 화면 스레드 밖에서 한다.

## 그림
- 타이틀 그림(key_home)은 영상이 도는 동안, 나머지 작은 그림(assets/ui, 마스코트, 유형 그림)은 타이틀에서 `warmImages` 로 미리 풀어 둔다. 처음 여는 화면에서 그림이 늦게 뜨지 않게.
- 새 그림을 넣을 때 화면에 쓰는 크기보다 훨씬 크게 넣지 말 것(지금 그림은 대부분 320~750px).

## 화면 그리기
- 아래 메뉴 탭(`main.dart` `_TabPage`)은 보고 있는 탭만 다시 그린다. 검사 중 답할 때마다 기록이 저장되며 화면 전체가 다시 그려지던 것을 줄였다.
- 안드로이드 화면 넘김은 `QuickPageTransitions`(0.22초, 살짝 밀며 나타남). 플러터 기본(0.45초, 전체 겹쳐 흐리기)은 손그림 화면에서 느리게 느껴진다. iOS 는 밀어서 뒤로 가기 때문에 기본 그대로.
